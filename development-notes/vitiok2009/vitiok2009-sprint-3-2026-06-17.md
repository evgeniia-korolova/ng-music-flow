# Sprint 3: UI Refactoring, Breadcrumbs Architecture & Bugfixes

**What I did:**

- Abstracted the `ScrollToTop` logic into a separate standalone component for better reusability.
- Adjusted the global layout by moving the footer above the global audio player.
- Implemented a smart, scalable Breadcrumbs widget.
- Refactored UI components (Artist and Album cards). Implemented the Template Reuse pattern using `<ng-template>` and `*ngTemplateOutlet`. Now, non-clickable cards render semantically as `<article>` without dead links or duplicated HTML.
- Fixed the "Unknown Artist / Album" display bug on the album profile page by expanding DTO interfaces.

**Problems:**

- **Routing & Breadcrumbs:** Initially, building the breadcrumbs logic led to a rapidly growing "if-else" hell based on parsing URLs, which wasn't scalable.
- **Data Mapping:** The `mapTrack` utility was returning "Unknown" instead of real names. The issue was that album/artist data only comes at the root level of the API response, not inside the tracks array, causing the mapper to get `undefined`.

**Solutions:**

- **Breadcrumbs:** Collaborated with AI (Gemini) to implement a declarative routing approach. Passed a `data` object (with `parentLabel`, `parentUrl`, and `skipBreadcrumb`) directly into the Angular Router config. The BreadcrumbsService now acts as a clean, "dumb" reader of this config, eliminating all hardcoded `if` statements.
- **Data Mapping:** During the track array iteration in `loadAlbumDetails`, I used destructuring to create new track objects, manually injecting the `album_name` and `artist_name` from the parent object before passing them to the mapper.
