# Sprint 2: Refactoring Artist Profile & Album Details

- **What was done:** Implemented the `artist-profile` page (Smart Component), which renders child dumb components: `artist-card`, lists of `album-card`, and `track-card`. Configured routing — clicking on an album opens a new `album-profile` page with album details. Designed new TypeScript interfaces (DTO and Domain models) and created a dedicated `AlbumStore` (based on NgRx SignalStore) for album state management. Fixed unit tests for components using new Signal Inputs (`input.required()`).

- **Problems:** It was challenging to grasp the concept of DTO (Data Transfer Object) and figure out how to correctly map raw backend data for the UI. The second issue was the "waterfall" effect of requests on the `artist-profile` page. Child components were making independent API calls, causing the UI to load in chunks and jump. In tests, I encountered the `NG0950: Input is required` error because TestBed wasn't passing data to the new signals during initialization.

- **Solutions:** Analyzed the logic line by line with the help of AI (Gemini). To handle the data, I applied a mapper function: it intercepts raw server data and transforms it into a clean Domain model before saving it to the Store. Resolved the waterfall issue by moving the loading logic to the parent `ArtistStore` and using the RxJS `forkJoin` operator. Now all three requests (artist, albums, tracks) run in parallel, and the state updates at once. In tests, added `fixture.componentRef.setInput(...)` before `detectChanges()`.

- **What I learned:**
  1. Realized the critical importance of optimizing network requests: replacing sequential requests with a single parallel one drastically improves UX.
  2. Clearly understood the difference between raw data (DTO) and the Domain Model. Now I see why mappers are needed — they make UI components independent of the backend structure.
  3. Deepened my understanding of `rxMethod` in NgRx SignalStore: learned how to connect signals, RxJS pipes (`switchMap`, `forkJoin`), and side effects (`tapResponse`) into a single stream.

- **Plans:** In the next sprint, I plan to implement pagination (a "Load More" button) for the tracks list so data loads in chunks. Also planning to allocate time to review and solidify the theoretical topics from last week.

- **Time spent:** ~20 hours (including architecture refactoring, debugging, and learning new patterns).
