# Sprint 4: Forms Architecture, Docker Integration & UI Development

**What I did:**

- Created a new playlist form with track selection using Reactive Forms. Added basic validation and typing interfaces, and reused an existing button component.
- Extracted the sidebar (`aside`) into an independent component and set up its adaptive design.
- Abstracted common styles for two forms into a single shared file for reusability.
- Extracted form navigation logic and the close function into a dedicated standalone service.
- Created a store for custom tracks and integrated the API service for backend communication.
- Improved the `onAddCustomTrack` method by adding duplicate validation and corresponding error messages if the track is already in the playlist.

**Problems:**

- **Forms & Layout:** Struggled initially with Reactive Forms syntax and object passing. Writing the sidebar layout directly inside the `library` component quickly led to cluttered code.
- **Adaptive UI:** Anticipated that converting the sidebar into a burger menu on screens smaller than 768px would require complex logic.
- **Docker & Networking:** Had no prior experience with real requests in a Docker environment. Faced major difficulties connecting the local app to the backend and database hosted in a VirtualBox VM container.

**Solutions:**

- **Architecture & Forms:** Collaborated with Gemini to implement the reactive form following Angular documentation. Separated the sidebar into its own component and moved navigation logic into a service to prevent code bloat.
- **Styling:** Successfully implemented the mobile burger menu purely through SCSS without extra logic. Spent time aligning the new form styles with the existing validation form to maintain visual consistency.
- **Infrastructure:** Resolved networking issues by configuring Port Forwarding in VirtualBox, allowing the local app to correctly execute requests to the Docker container.
- **Validation:** Implemented duplicate track error messages using reactive signals.
